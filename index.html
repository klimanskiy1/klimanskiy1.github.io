How I work

The same path for a site and for a product

Understand what exists, write it down as data and rules, build, check, ship. AI coding agents do a lot of the typing; their output is a pull request from someone else, never finished work.

  1. Audit

    For a site: every page, price, course, photo and link of the live one. For a product: the problem, the scenarios, the risks, written down before code.

  2. Spec

    Text and prices go into data files, the schema into migrations, the red lines into a decision log. Pages and endpoints are written by code.

  3. Build

    Site builders in Python, backends in TypeScript or Python. Coding agents get a narrow brief and a scoped task, not the whole repo.

  4. Verify

    Guard linter and hooks run in CI, tests hit a real database, and a separate security pass only reports findings. It never patches.

  5. Ship

    A green check does not replace looking at the result. Then a static host, or a VPS behind Docker with a backup that has been restored at least once.

Nothing gets invented. A rebuilt site carries the business's own text, prices, courses and photos 1:1. The design changes; the facts do not. If the original lists 95 dive sites, the new one lists 95 dive sites.

Content as data, pages as code. Every site ships with a small generator: change a price in one file and every page, language and sitemap follows. No page builder, no plugins, no database to keep alive.

A rule that exists only in prose is a suggestion. In my own products the constraints live in a guard linter and pre-commit hooks, mirrored in CI. WipeSquad has sixteen of them, from “identity comes only from the server session” to “no copyleft in server code”.

Agents type; I accept. I use coding agents heavily and say so. They never review their own output, a security pass runs separately, and CI actions are pinned by commit SHA with read-only tokens, because build steps run third-party code next to your credentials.
