How a project goes

The same path for a site rebuild and for my own products: understand what exists, write it down as data and rules, build, check, ship. I use AI coding agents for a lot of the typing and treat their output like a pull request from someone else, never as finished work.

AuditTake stock of what exists

For a site: every page, price, course, photo and link of the live one. For a product: the problem, the scenarios, the risks, written down before code.

SpecContent as data, rules as rules

Text and prices go into data files, the schema into migrations, the red lines into a decision log. Pages and endpoints are written by code.

BuildGenerators and agents do the typing

Site builders in Python, backends in TypeScript or Python. Coding agents get a narrow brief and a scoped task, not the whole repo.

VerifyNothing reviews its own work

Guard linter and hooks run in CI, tests hit a real database, and security review is a separate pass that only reports findings. It never patches.

ShipGreen check, own eyes, deploy

A passing pipeline does not replace looking at the result. Then it goes to a static host or a VPS behind Docker, with a backup that has been restored at least once.

anything that fails the check goes back to the spec, not to a hand patch
01 · content

Nothing gets invented

A rebuilt site carries the business's own text, prices, courses and photos 1:1. The design changes; the facts do not. If the original lists 95 dive sites, the new one lists 95 dive sites.

02 · data

Content as data, pages as code

Every site ships with a small generator: change a price in one file and every page, language and sitemap follows. No page builder, no plugins, no database to keep alive.

03 · rules

A rule that exists only in prose is a suggestion

In my own products the constraints live in a guard linter and pre-commit hooks, mirrored in CI. WipeSquad has 16 of them, from “identity comes only from the server session” to “no copyleft in server code”, each backed by a check.

04 · agents

Agents type; I accept

I use coding agents heavily and say so. They never review their own output, a security pass runs separately and only reports, and CI actions are pinned by commit SHA with read-only tokens, because build steps run third-party code next to your credentials.
